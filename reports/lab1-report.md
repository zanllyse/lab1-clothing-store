# Звіт до лабораторної роботи № 01

## Тема
Розроблення backend архітектури та основного функціоналу.

## Мета роботи
Отримати практичні навички створення серверної частини вебдодатку з використанням Node.js та Express.js, налаштувати PostgreSQL і реалізувати базові операції з даними.

## 1. Обрана предметна область

Для розробки обрано предметну область **«Інтернет-магазин одягу»**. Система призначена для зберігання інформації про категорії та товари, клієнтів і замовлення.

У базі даних створено п’ять сутностей:
- Category — категорії товарів;
- Product — товари магазину;
- Customer — клієнти та їхні ролі;
- Order — замовлення клієнтів;
- OrderItem — товари, що входять до замовлення.

Зв’язки: одна категорія містить багато товарів; один клієнт може мати багато замовлень; одне замовлення містить багато позицій; один товар може зустрічатися в різних позиціях замовлень. Таким чином реалізовано зв’язки «один-до-багатьох» та зв’язок між замовленнями й товарами через проміжну таблицю OrderItem.

## 2. Використані технології

- **Node.js** — середовище виконання JavaScript на сервері.
- **Express.js** — фреймворк для створення HTTP-сервера та маршрутів.
- **PostgreSQL** — реляційна база даних.
- **Prisma ORM** — інструмент для опису моделей і роботи з базою даних.
- **Zod** — бібліотека для перевірки вхідних даних.
- **dotenv** — завантаження налаштувань із файлу `.env`.

## 4. Реалізація API

Для кожного ресурсу доступні основні CRUD-операції:

| Метод | Призначення |
|---|---|
| GET /api/resource | Отримати список записів |
| GET /api/resource/:id | Отримати один запис |
| POST /api/resource | Створити запис |
| PUT /api/resource/:id | Оновити запис |
| DELETE /api/resource/:id | Видалити запис |

Ресурси API: `categories`, `products`, `customers`, `orders`, `order-items`.

## 5. Валідація та обробка помилок

Для перевірки даних використовується Zod. Перевіряються обов’язкові текстові поля, формат електронної пошти, додатна ціна, невід’ємний залишок товару та коректні числові ідентифікатори. Якщо дані не проходять перевірку, сервер повертає статус HTTP 400 з описом помилок.

Також реалізовано централізовану обробку помилок: 404 для відсутнього запису або маршруту, 409 для порушення унікальності та 500 для внутрішньої помилки сервера.

## 6. Налаштування середовища

Параметри підключення до бази даних і порт сервера зберігаються у `.env`. Приклад налаштувань наведено у `.env.example`. Файл `.env` не додається до Git-репозиторію, оскільки може містити пароль.

## 7. Перевірка роботи

Після створення бази даних, встановлення залежностей і виконання міграції сервер запускається командою `npm run dev`. Перевірити доступність API можна за адресою `http://localhost:3000/api`.

Для тестування окремих операцій можна використати Postman або curl. Приклади запитів наведені у README.md.

**Місце для скріншотів:** після запуску проєкту додати скріншот сервера в терміналі, відповідь GET-запиту та результат створення запису через POST-запит.

## Висновок

Під час виконання лабораторної роботи було створено базову серверну частину вебдодатку інтернет-магазину одягу. Налаштовано Express.js, підключення до PostgreSQL через Prisma ORM, описано п’ять пов’язаних моделей і реалізовано CRUD-маршрути. Також додано базову валідацію даних, обробку помилок і конфігурацію через змінні середовища. Поставленої мети досягнуто.
